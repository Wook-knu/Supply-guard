# SupplyGuard 벤치마크 기능 정의

> 이 문서는 SupplyGuard 벤치마크가 어떤 데이터를 비교하고, 사용자가 무엇을 판단할 수 있으며,
> 어떤 데이터는 사용하지 않는지를 설명하는 기준 문서다.

> **현재 구현 기준 문서**: 이 문서는 고객사 데이터를 사용하지 않는 현재 기능(As-Is)을 설명한다.  
> 고객사 익명 집계 데이터를 활용하는 향후 확장안과 회의 안건은
> [고객사 데이터 기반 벤치마크 확장 검토안](benchmark-expansion-meeting-2026-08-04.md)에서 별도로 관리한다.

## 1. 한 문장 정의

SupplyGuard 벤치마크는 **다른 고객사의 구매·운영 데이터를 비교하는 기능이 아니다.**

현재 기능은 다음 두 가지 상대 위치를 보여준다.

1. 품목·국가: SupplyGuard가 공개 공급망 데이터를 이용해 계산한 **SGRI 데이터셋 내 상대 위치**
2. 공급사: 현재 품목에 추천된 **후보 공급사 집합 내 조달 참고지표 순위**

따라서 이 기능으로 알 수 있는 것은 “다른 중소기업이 어떤 결정을 내렸는가”가 아니라,
“현재 품목·국가·공급사가 비교 대상 안에서 상대적으로 어디에 위치하는가”이다.

## 2. 비교 대상과 데이터 범위

| 구분 | 비교 대상 | 사용하는 데이터 | 사용하지 않는 데이터 |
|---|---|---|---|
| 품목 벤치마크 | 선택한 HS 품목 vs 전체 HS 품목·국가 | 국가별 SGRI와 S·C·V·L·P·E 지표 | 다른 고객사의 구매량, 계약가격, 재고, 발주 이력 |
| 국가 벤치마크 | 같은 HS 품목에 포함된 국가 후보 | 해당 국가 SGRI, 품목 평균, 후보국 수 | 특정 고객사가 선택한 공급국, 계약 결과 |
| 공급사 벤치마크 | 현재 `query_id`에 추천된 공급사 후보 | `companies`에 등록된 단가·리드타임·정시납품률·불량률 참고값 | 다른 고객사의 실구매 단가, 협상조건, 평가 메모 |
| 보고서 작성 근거 | 선택 품목 vs 전체 데이터셋 | 품목 평균 SGRI, 전체 평균, 차이와 판정 | 다른 고객사의 보고서와 내부 의사결정 |

### “같은 품목을 가진 다른 회사 데이터”인가?

아니다. 현재 품목 벤치마크의 비교 단위는 **고객사**가 아니라 `국가 × HS 품목` 위험 데이터다.

- 선택 품목 평균: 해당 HS 코드에 존재하는 국가별 SGRI의 평균
- 전체 평균: SGRI 데이터셋에 존재하는 모든 HS 품목·국가 행의 평균
- 국가 상대 위치: 동일 HS 코드의 국가 후보들 사이에서 계산
- 공급사 상대 위치: 동일 조달 질의에 추천된 공급사 후보들 사이에서 계산

공급사 후보의 참고지표는 공급사 엔터티에 등록된 값이며, 플랫폼 고객사의 구매 실적을 모아 만든 값이 아니다.

## 3. 사용자가 얻는 것

### 3.1 어떤 품목부터 대응할지 결정

SGRI 점수 하나만 보면 위험의 크기를 해석하기 어렵다. 품목 평균과 전체 평균을 같이 보여주면 사용자는 다음을 알 수 있다.

- 이 품목이 전체 데이터셋보다 위험한지 또는 안전한지
- 전체 평균과 몇 점 차이가 나는지
- 6개 지표 중 어떤 항목이 평균보다 특히 위험한지

사용자는 평균보다 크게 높은 지표를 기준으로 공급처 다변화, 안전재고 검토, 정책·물류 모니터링의 우선순위를 정할 수 있다.

### 3.2 추천 국가를 검증

추천 순위만으로 국가를 결정하지 않고, 동일 품목의 후보국 안에서 상대적 위험 위치를 확인한다.

- 후보국 수
- 위험도 상위 백분위
- 해당 품목 평균 대비 SGRI 차이
- 평균보다 안전한지 또는 위험한지

이를 통해 사용자는 1순위 국가를 우선 검토할지, 2순위 국가를 보조 공급국으로 병행할지 판단할 수 있다.

### 3.3 공급사 쇼트리스트 작성

공급사 상세에서는 현재 추천 후보들만을 기준으로 다음 지표의 값·평균·순위를 보여준다.

- 예상 단가: 낮을수록 우수
- 리드타임: 짧을수록 우수
- 정시 납품률: 높을수록 우수
- 불량률: 낮을수록 우수

사용자는 가격, 납기, 품질 중 자사 우선순위에 맞춰 견적·샘플을 요청할 공급사를 고를 수 있다.

### 3.4 보고서의 수치 근거 확인

보고서 작성 화면은 다음 수치를 함께 보여준다.

- 선택 품목 평균 SGRI
- 전체 품목 평균 SGRI
- 평균 대비 차이
- `평균보다 위험 / 평균 수준 / 평균보다 안전` 판정

이 정보는 AI 의견을 대신하지 않으며, 사용자가 보고서를 생성하기 전에 분석의 상대적 위치를 확인하는 근거다.

## 4. 계산 기준

### 4.1 품목 평균과 전체 평균

```text
품목 평균 SGRI = 선택한 HS 코드의 국가별 SGRI 평균
전체 평균 SGRI = 전체 HS 품목·국가의 SGRI 평균
차이 = 품목 평균 - 전체 평균
```

6개 지표도 같은 방식으로 품목 평균과 전체 평균을 비교한다.

### 4.2 판정

```text
차이 >= +5점  → 평균보다 위험
차이 <= -5점  → 평균보다 안전
그 사이        → 평균 수준
```

### 4.3 국가 위험 백분위

동일 HS 품목에 데이터가 있는 국가들을 SGRI 기준으로 비교한다. 화면의 `위험도 상위 N%`에서 N이 작을수록 해당 후보군 안에서 위험도가 높은 국가다.

이 값은 세계 모든 국가의 절대 순위가 아니라 **현재 데이터셋에 포함된 동일 품목 후보국 안의 상대 위치**다.

### 4.4 공급사 순위

동일 `query_id`의 추천 공급사 중 값이 존재하는 후보만 비교한다.

- 단가·리드타임·불량률: 작은 값부터 높은 순위
- 정시 납품률: 큰 값부터 높은 순위
- 후보 평균과의 차이가 약 3% 이내면 `평균 수준`
- 그 외에는 지표 방향에 따라 `우수` 또는 `미흡`

## 5. 화면에서의 위치

| 화면 | 표시 내용 | 사용자의 다음 행동 |
|---|---|---|
| `/risks/{hsCode}` | 품목·전체 평균, 6지표 차이, 대표 위험국 백분위 | 우선 대응 지표 확인, 대체 공급국 검토 |
| `/recommendations?query_id={id}` | 선택 국가의 후보국 내 위험 위치 | 추천 국가 검증, 보조 국가 병행 선택 |
| `/suppliers/{companyId}?query_id={id}` | 후보 공급사 평균·순위·판정 | 견적·샘플 요청 대상 선정 |
| `/reports/new?query_id={id}` | 보고서 작성 전 전체 평균 대비 근거 | 사내 보고 근거 확인 |

벤치마크는 별도 메뉴가 아니라 사용자가 실제 선택을 내리는 화면에 배치한다.

## 6. 개인정보·기업정보 보호 원칙

현재 구현은 고객사 간 데이터를 섞어 비교하지 않는다. 다음 정보는 벤치마크 계산에 사용하지 않는다.

- 고객사명, 담당자, 계정 정보
- 고객사의 실제 구매량과 발주 이력
- 실제 계약가격, 협상조건, 거래처
- 재고량과 생산계획
- 검토 보드 메모와 AI 보고서 내용
- 다른 고객사의 추천 선택·피드백 내역

화면에는 `타사 고객정보를 사용하지 않습니다`라는 기준을 표시한다.

향후 “유사 중소기업의 대응 방식”을 제공하려면 현재 벤치마크와 분리된 기능으로 설계해야 한다. 명시적 동의, 최소 표본 수, 범위·중앙값 중심 집계, 소수 집단 비공개, 재식별 위험 검토가 선행되지 않으면 고객사 기반 비교를 제공하지 않는다. 구체적인 제안은 [2026년 8월 4일 회의 검토안](benchmark-expansion-meeting-2026-08-04.md)을 따른다.

## 7. 한계와 해석 주의사항

- 현재 데이터셋 안의 상대 위치이며 시장 전체를 대표하지 않는다.
- SGRI는 위험 대응 우선순위를 돕는 지표이며 미래 사고를 확정적으로 예측하지 않는다.
- 공급사 지표는 실제 견적이나 계약 조건이 아니라 공개·등록된 참고값이다.
- 값이 없는 후보는 해당 지표의 평균·순위 계산에서 제외된다.
- 데이터가 충분하지 않으면 화면에 `비교 데이터 부족` 상태를 표시한다.
- 실제 계약 전에는 최신 견적, MOQ, 인증, 납기, 품질을 담당자가 다시 확인해야 한다.

## 9. 배포·검증 체크리스트

GitHub 반영과 배포 전에 다음을 확인한다.

- 이 문서와 README 링크가 함께 커밋되었는가
- 벤치마크 API 두 개가 배포 백엔드에서 응답하는가
- 품목 데이터가 없을 때 `비교 데이터 부족`이 표시되는가
- 국가를 바꾸면 국가 백분위가 함께 바뀌는가
- 공급사 상세 URL에 `query_id`가 유지되는가
- 공급사 후보가 부족할 때 순위를 과장하지 않는가
- 화면의 기준 문구와 API의 `basis`가 일치하는가
- 고객사 데이터로 오해할 표현이 없는가
