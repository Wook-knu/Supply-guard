# 고객사 데이터 기반 벤치마크 확장 검토안

> 회의 예정일: **2026년 8월 4일 화요일**  
> 목적: 현재 공개·등록 데이터 기반 벤치마크와 향후 고객사 익명 집계 벤치마크를 구분하고,
> 확장 여부·데이터 범위·보호 기준을 결정한다.

## 1. 회의에서 먼저 확인할 결론

현재 구현된 벤치마크는 **다른 고객사의 구매·계약·운영 데이터를 사용하지 않는다.**

현재 기능과 향후 확장안은 다음처럼 구분한다.

| 구분 | 현재 구현 | 확장 검토안 |
|---|---|---|
| 기능명 제안 | 데이터셋 상대 벤치마크 | 동종 중소기업 대응 동향 |
| 핵심 질문 | 이 품목·국가·공급사는 데이터셋 안에서 어느 위치인가 | 비슷한 기업은 어떤 대응을 선택했고 결과가 어땠는가 |
| 데이터 | 공개 공급망 데이터로 계산한 SGRI, 공급사 공개·등록 참고지표 | 참여에 동의한 고객사의 정형 운영 데이터에서 만든 익명 집계 |
| 고객사 원데이터 사용 | 사용하지 않음 | 조건부 사용 검토 |
| 현재 개발 상태 | API·프론트 연결 완료 | 정책·법률·데이터 구조부터 신규 설계 필요 |

회의에서는 기존 기능을 변경할지보다, **두 번째 기능을 별도 기능으로 추가할 것인지**를 결정하는 것이 핵심이다.

## 2. 현재 구현 상태(As-Is)

현재 기능의 상세 기준은 [SupplyGuard 벤치마크 기능 정의](benchmark.md)를 따른다.

### 2.1 품목 벤치마크

- 선택한 HS 품목의 국가별 SGRI 평균을 계산한다.
- 전체 SGRI 데이터셋의 모든 `HS 품목 × 국가` 평균과 비교한다.
- S·C·V·L·P·E 6개 지표도 품목 평균과 전체 평균을 비교한다.
- 차이가 `+5점 이상`이면 평균보다 위험, `-5점 이하`이면 평균보다 안전, 그 사이는 평균 수준으로 표시한다.

사용자가 얻는 것:

- 어떤 품목부터 대응해야 하는지
- 6개 지표 중 무엇을 우선 확인해야 하는지
- 공급처 다변화·안전재고·정책 모니터링 중 무엇을 먼저 검토할지

### 2.2 국가 벤치마크

- 동일 HS 품목에 데이터가 있는 국가 후보끼리 SGRI를 비교한다.
- 선택 국가가 후보국 중 위험도 상위 몇 퍼센트인지 표시한다.
- 해당 국가가 품목 평균보다 얼마나 위험하거나 안전한지 표시한다.

사용자가 얻는 것:

- 추천 1위 국가가 실제로 상대적으로 안전한지 검증
- 1개 국가로 전환할지, 2순위 국가를 보조 공급국으로 병행할지 판단

### 2.3 공급사 벤치마크

- 동일 `query_id`에 추천된 공급사 후보끼리 비교한다.
- `companies` 테이블에 등록된 단가·리드타임·정시 납품률·불량률 참고값을 사용한다.
- 단가·리드타임·불량률은 낮을수록, 정시 납품률은 높을수록 우수한 순위로 표시한다.

사용자가 얻는 것:

- 가격·납기·품질 중 자사 우선순위에 맞는 공급사 선택
- 견적·샘플을 요청할 공급사 쇼트리스트 작성

### 2.4 보고서 작성 화면

- 품목 평균 SGRI, 전체 평균, 차이와 판정을 표시한다.
- AI 보고서 생성 전 사용자가 상대 비교 근거를 확인하도록 돕는다.

### 2.5 현재 사용하지 않는 데이터

현재 벤치마크는 다음 고객사 정보를 사용하지 않는다.

- 고객사명·담당자·계정 정보
- 실제 구매량·발주 이력·재고량
- 실제 계약가격·협상조건·거래처
- 검토 보드 메모와 AI 보고서
- 다른 고객사의 추천 선택·피드백

따라서 현재 구현은 “다른 중소기업의 대응 사례” 기능이 아니다.

## 3. 확장 기능의 목적(To-Be)

확장안의 목적은 중소기업 사용자가 다음 질문에 답을 얻도록 하는 것이다.

- 우리와 비슷한 기업은 단일 공급처를 유지했는가, 복수 공급처로 전환했는가
- 안전재고를 얼마나 확보했는가
- 대응 후 비용·납기·공급 중단 위험이 어떻게 달라졌는가
- 전면 전환과 일부 물량 분산 중 어떤 방식이 더 많이 사용됐는가

사용자에게 개별 기업 사례를 보여주는 것이 아니라, **충분한 표본에서 계산한 익명 집계 동향**을 보여주는 방향이다.

## 4. 활용을 검토할 고객사 데이터

원본을 그대로 노출하지 않고 다음과 같은 정형 지표로 변환한다.

| 원본 또는 이벤트 | 저장·표시할 집계값 예시 |
|---|---|
| 공급국 수 | 유사 기업의 중앙값, 구간별 비율 |
| 복수 공급처 도입 여부 | 도입 기업 비율 |
| 안전재고 일수 | 중앙값·사분위 범위 |
| 공급사 전환 비중 | `0~20%`, `20~50%`, `50% 이상` 구간 비율 |
| 조달비용 변화 | 정확한 금액이 아닌 증감률 범위 |
| 리드타임 변화 | 단축·증가 일수 범위 |
| 납기 지연 여부 | 기간별 발생률 변화 |
| 대응 전후 SGRI | 평균적인 점수 변화 범위 |

### 수집 대상에서 제외할 정보

- 기업명과 사업자등록번호
- 담당자 이름·이메일·전화번호
- 공급사 실명과 계약서
- 정확한 구매단가·구매량·발주일
- 자유 입력 메모와 첨부파일
- 특정 기업을 식별할 수 있는 지역·업종·시점 조합
- 고객 동의를 받지 않은 기존 서비스 데이터의 소급 활용

## 5. 사용자 화면 예시

```text
동일 HS 품목·유사 규모 기업 24개사의 익명 집계
집계 기간: 최근 12개월

복수 공급처 운영             63%
공급국 수 중앙값             2개국
안전재고 중앙값              21~35일
공급처 추가 후 비용 변화      +2~5%
공급처 추가 후 리드타임 변화  3~8일 단축
```

화면에는 반드시 다음을 함께 표시한다.

- 비교 집단 선정 기준
- 참여 기업 수
- 집계 기간
- 중앙값·범위·비율인지 여부
- `개별 기업의 성과를 보장하지 않는다`는 한계
- 표본이 부족한 경우 `비교 데이터 부족` 상태

## 6. 개인정보·영업정보 보호 기준

### 6.1 법률 적용 범위 구분

- 법인 자체의 일반 정보가 항상 개인정보인 것은 아니다.
- 담당자·대표자·개인사업자 정보가 결합되면 개인정보가 될 수 있다.
- 계약가격·구매량·공급사·생산계획은 개인정보 여부와 별개로 영업비밀 또는 계약상 비밀정보가 될 수 있다.

따라서 개인정보보호법만 검토해서는 충분하지 않고, 이용약관·고객 계약·비밀유지 의무를 함께 검토해야 한다.

### 6.2 권장 동의 방식

서비스 가입에 묶인 포괄 동의보다 별도의 선택 동의를 권장한다.

```text
[선택] 익명 벤치마크 데이터 기여

목적: 동종 기업의 공급망 대응 통계 제공
항목: 공급국 수, 대응 유형, 비용·납기 변화 구간
처리: 식별자 제거 후 최소 표본 기준을 충족한 집계값만 제공
보유기간: 집계 목적 달성 또는 동의 철회 시까지의 정책 명시
철회: 설정 화면에서 언제든 철회 가능
```

개인정보보호법의 가명정보 특례가 상업용 고객 벤치마크에 자동으로 적용된다고 전제하지 않는다. 실제 수집 전에 법률 전문가 또는 개인정보 보호책임자의 검토를 받는다.

### 6.3 제품 내부 보호 기준 제안

아래 숫자는 법률상 일률적인 면책 기준이 아니라 회의에서 결정할 내부 보수 기준이다.

- 기본 공개 기준: 동일 비교집단에 최소 20개 기업
- 제한적 공개 하한: 법률·위험 검토 후 최소 10개 기업
- 기준 미만 집단: 결과 전체 비공개
- 한 기업은 기간별 지표에 한 번만 기여
- 평균보다 중앙값·사분위 범위를 우선 사용
- 가격·수량·날짜는 구간화·반올림
- 최신 계약 데이터는 일정 기간 지연 후 집계
- 세부 필터 조합으로 표본을 기준 미만까지 좁힐 수 없게 제한
- 특정 기업의 영향이 지나치게 크면 결과 비공개 또는 기여도 제한
- 외부 LLM에는 고객사 원데이터를 전달하지 않고 승인된 집계값만 전달

개인정보위의 2026년 가명정보 처리 가이드라인은 사전 준비, 위험성 검토, 가명처리, 적정성 검토, 안전한 관리 절차를 제시한다. 가명정보를 처리할 경우 복원용 추가정보의 분리와 안전성 확보조치도 필요하다.

## 7. 권장 시스템 구조

```text
고객별 원본 데이터(tenant 영역)
        ↓
목적·동의 여부 검사
        ↓
식별자 제거 + 범위화 + 기업별 기여도 제한
        ↓
최소 표본 수·재식별 위험 검사(privacy gate)
        ↓
업종·규모·HS·기간별 집계 테이블
        ↓
고객 화면 API는 집계 테이블만 조회
```

### 저장소 분리

- 원본 운영 DB와 벤치마크 집계 DB 또는 스키마를 분리한다.
- 고객 ID와 집계 레코드의 연결키는 별도 보관하거나 집계 완료 후 제거한다.
- 프론트엔드 API는 원본 행을 반환하지 않는다.
- 접근권한·접속기록·보유기간·삭제 절차를 운영 문서에 포함한다.

## 8. 단계별 도입안

### 0단계 — 현재

- 공개 공급망 데이터 기반 SGRI 상대 벤치마크 유지
- 고객사 데이터 사용 없음

### 1단계 — 정책·데이터 설계

- 선택 동의문과 이용약관 검토
- 수집할 정형 지표 최소화
- 비교집단과 최소 표본 기준 확정
- 개인정보·영업비밀 위험성 검토

### 2단계 — 비공개 수집·내부 검증

- 동의 기업만 데이터 기여
- 고객 화면에는 아직 공개하지 않음
- 표본 수, 이상치, 재식별 가능성, 통계 안정성을 내부 평가

### 3단계 — 제한된 집계 베타

- 표본이 충분한 HS·업종만 공개
- 중앙값·범위·비율만 제공
- 필터와 다운로드 기능 제한
- 고객 피드백과 철회 절차 검증

### 4단계 — 정식 기능

- 법률·보안 검토 완료 후 제공
- 데이터 품질·표본·집계 기간을 화면에 상시 고지
- 정기적인 재식별 위험 검토와 접근 기록 감사

## 9. 회의 결정 안건

### 필수 결정

1. 고객사 데이터 기반 기능을 실제 제품 범위에 포함할 것인가
2. 기능명을 `동종 중소기업 대응 동향`으로 분리할 것인가
3. 어떤 데이터를 선택 동의 대상으로 수집할 것인가
4. 기존 고객 데이터는 사용하지 않고 동의 이후 데이터만 사용할 것인가
5. 기본 최소 표본을 20개 기업으로 설정할 것인가
6. 비교집단을 `HS 코드 + 업종 + 기업 규모` 중 어디까지 세분화할 것인가
7. 정확한 평균 대신 중앙값·범위·비율만 제공할 것인가
8. 외부 AI에는 집계값만 전달하도록 제한할 것인가
9. 이용약관·동의문·개인정보처리방침 검토 담당자는 누구인가

### 데이터·사업 결정

1. 사용자에게 가장 가치 있는 결과가 비용, 납기, 공급 안정성 중 무엇인가
2. 충분한 고객 표본을 언제 확보할 수 있는가
3. 공공기관·협회·설문 데이터를 먼저 활용할 수 있는가
4. 해당 기능을 Basic, Pro, Enterprise 중 어느 요금제에 제공할 것인가
5. 사례 공개가 필요한 경우 별도 서면 동의를 어떻게 받을 것인가

## 10. 회의 권고안

현재 시점의 권고안은 다음과 같다.

1. 현재 SGRI 상대 벤치마크를 먼저 안정적으로 운영한다.
2. 고객사 기반 기능은 기존 기능에 섞지 않고 별도 기능으로 정의한다.
3. 고객사 원데이터를 바로 화면에 활용하지 않는다.
4. 선택 동의와 최소 표본 기준이 확정되기 전에는 개발을 시작하지 않는다.
5. 초기 확장은 공공 통계·익명 설문 데이터로 검증한다.
6. 플랫폼 고객 데이터는 충분한 참여 기업과 법률·보안 검토가 확보된 이후에만 제한적으로 집계한다.
