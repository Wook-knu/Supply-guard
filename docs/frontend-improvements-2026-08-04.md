## 1. 모바일 화면 글자깨짐

### 1-1. 카드가 화면을 넘쳐 잘리던 문제

Tailwind에서 `grid`만 쓰고 기본 `grid-cols-*`를 생략하면, 모바일 단일 컬럼 트랙이 `auto`가 됩니다.
`auto` 트랙은 `minmax(min-content, max-content)`라서 **내용보다 좁아질 수 없습니다.**
카드 안에 `truncate`(`white-space: nowrap`)가 있으면 그 텍스트 전체 길이가 min-content가 되어
트랙을 밀어올리고, 같은 트랙의 카드가 **모두** 함께 커집니다.

`grid-cols-1`은 트랙을 `repeat(1, minmax(0, 1fr))`로 만들어 최소폭을 0으로 고정합니다.
미디어쿼리가 없는 기본값이므로 `lg:grid-cols-3` 등 데스크탑 설정은 그대로 유지됩니다.

| 페이지 | 문서 폭 (375px 화면) | 조치 |
|---|---|---|
| `/dashboard` | 425px → **375px** | 그리드 3곳 `grid-cols-1` |
| `/trends` | 491px → **375px** | 그리드 3곳 `grid-cols-1` |
| `/risks/[hsCode]` | 391px → **375px** | 그리드 3곳 `grid-cols-1` |
| `/compare` | 카드 잘림 → 정상 | `<select>` 그리드를 `minmax(0,1fr)`로, select에 `w-full min-w-0` |

앱 전체 28곳을 스캔했지만 **실제로 넘치는 곳은 위 4개뿐**이었습니다.
나머지는 구조상 후보였을 뿐 내용이 짧아 문제가 없어 손대지 않았습니다.

### 1-2. 버튼·제목 글자가 세로로 쪼개지던 문제

`flex justify-between` 헤더에서 우측 버튼이 `whitespace-nowrap`이라 줄어들지 않고,
좌측 열에 `min-w-0`이 없어 제목이 짜부라졌습니다.

| 위치 | 증상 | 조치 |
|---|---|---|
| `/reports/new` AI 초안 미리보기 | 보고서 제목이 한 글자씩 세로로 꺾임 | 모바일 세로 배치(`flex-col` → `sm:flex-row`), 제목 열 `min-w-0 flex-1`, 버튼 묶음 `shrink-0 flex-wrap` |
| `/dashboard` 국가 위험도·기업 적합도 헤더 | `전체` → `전`/`체`, `위험 높은순` → 2줄 (높이 46px) | 헤더 모바일 세로 배치, 버튼에 `shrink-0 whitespace-nowrap` (높이 28px로 정상화) |

라벨도 `위험 높은순` → **`위험도 높은순`** 으로 변경했습니다. 아래 `적합도 높은순`과 짝이 맞고,
줄바꿈되어도 첫 줄이 `위험도`로 완결됩니다.

## 3. 최신 동향 → 실제 뉴스로 교체

### 변경 내용

기존에는 알림(`GET /alerts`) 상위 4건을 보여주고, 클릭하면 `/risks/{hs}`(리스크 분석)로 갔습니다.
이제 수집된 실제 뉴스를 우선 표시하고 **클릭하면 원문으로** 이동합니다.

```
api.getRealNews(hs_code)  →  GET /benchmark/real-news/{hs_code}
                          →  backend/app/services/real_cases.py
                          →  GDELT DOC 2.0 API (무료·무키)
```

- 카드명: `최신 동향` → **`최신 공급망 뉴스`**
- 각 행에 `출처 {언론사 도메인} · {날짜}` 표기
- 뉴스가 없거나 조회 실패 시에만 알림으로 대체(이때도 `source_url`이 있으면 원문으로)
- 제목이 잘리지 않게 `truncate` → `break-words`

### 알아둘 한계

| 항목 | 현황 |
|---|---|
| 뉴스 소스 | **GDELT 하나뿐** — 네이버·빅카인즈 등 국내 소스는 코드베이스에 없음 |
| 언어 커버리지 | GDELT는 영어 기사 위주. `hs_codes.name_en` 으로 검색하므로 **해외 기사가 주로 나옴** |
| `name_en` 이 비면 | 한글명으로 검색 → 결과 거의 없음 → 빈 배열 → 알림으로 폴백 |
| 캐시 | 없음. 매 요청마다 외부 호출(타임아웃 15초) — 단일 장애점 |
| 알림의 `source_url` | 특정 기사가 아니라 **구글뉴스 검색 URL** (`alerts_gen.py:45`) |

국내 기사 커버리지를 높이려면 네이버 뉴스 검색 API 등 별도 소스가 필요하고, 이는 백엔드 작업입니다.

**미완료:** `/trends` 페이지에는 아직 뉴스 목록이 없습니다(AI 요약·차트만). 별도 작업으로 남았습니다.

## 4. 모바일 내비게이션 신규 추가

### 발견한 문제

사이드바가 `hidden lg:flex`인데 이를 대체할 모바일 내비게이션이 없어,
**모바일에서 메뉴 10곳 중 8곳에 도달할 수 없었습니다.**

측정 결과(모바일 대시보드에서 도달 가능 여부):

| 도달 가능 | 도달 불가 |
|---|---|
| 글로벌 지도, 검토 보드 | 대시보드(홈), 내 품목, SGRI 비교하기, 벤치마크, AI 보고서, 요금제, 설정, **최신동향 분석** |

`최신동향 분석`은 사이드바 맨 아래 배너가 유일한 진입점이었고, 그 배너는
① `lg` 미만에서 사이드바 자체가 사라지고 ② 사이드바를 접으면 숨겨져,
**1024px 이상 + 펼친 상태 + 맨 아래까지 스크롤** 이라는 세 조건을 모두 만족해야만 보였습니다.

### 조치 — `app/(app)/layout.tsx`

하단 고정 탭바(`lg:hidden`) + `더보기` 시트를 추가했습니다.

```
탭바 5개:  대시보드 · 내 품목 · 글로벌 지도 · 최신동향 · 더보기
더보기 시트: SGRI 비교하기 · 벤치마크 · 검토 보드 · AI 보고서 · 요금제 · 설정
```

- 라우트 변경 시 시트 자동 닫힘, 시트 열림 중 배경 스크롤 차단
- 콘텐츠에 `pb-16` 을 줘서 마지막 줄이 탭바에 가리지 않게 처리
- 챗봇 플로팅 버튼을 `bottom-20`(모바일)로 올려 탭바와 겹치지 않게 조정

결과: **10곳 전부 도달 가능**(실측 확인).

## 5. 가짜 데이터 제거 — `/alerts`

`initialAlerts` 상수로 가짜 알림 5건을 **초기 상태로 렌더링**하고 있었습니다.
`placeholder` 가 아니라 심각도 배지·시간·출처를 갖춘 정상 알림 카드라 실제 알림과 구분이 불가능했습니다.

가짜가 남는 경로가 두 개였습니다.

```js
api.getAlerts().then((rows) => {
  if (!rows.length) return      // 알림 0건인 신규 사용자 → 가짜 유지
  ...
}).catch(() => {})              // API 실패 → 가짜 유지
```

| 항목 | 조치 |
|---|---|
| `initialAlerts` 5건 | **삭제**, 초기값 `[]` |
| 빈 응답 / 실패 시 폴백 | 제거 → 로딩·오류·빈 상태를 각각 표시 |
| `즉시 확인 필요` 카드 | `리튬 탄산염의 위험도가…` 고정 문구 → 실제 알림 중 최고 심각도 건의 제목·본문 |

## 6. 하드코딩 제거 — HS `283691` / 품목명

특정 HS 코드와 품목명이 코드에 박혀 있었습니다.

| 파일 | 전 | 후 |
|---|---|---|
| `map` `benchmark` `compare` | `useState("283691")` | `useState("")` → API 첫 등록 품목 자동 선택 |
| `map` `benchmark` `compare` | `리튬 탄산염 (HS 283691)` 끼워넣기 옵션 | 삭제 |
| `risks/[hsCode]` | `HS_NAME = { "283691": "리튬 탄산염" }` | 삭제 → `queryName ?? HS {code}` |
| `settings` | `hs_code === "283691" ? "리튬 탄산염" : …` | `GET /queries` 의 `item_name` 사용 |

`settings` 는 `/risks` 응답에 품목명이 없어 `/queries` 를 함께 불러 HS→이름 맵을 만들었습니다.
그 결과 **모든 품목이 제 이름으로** 표시됩니다(전에는 283691만 이름이 나왔습니다).

### 함께 고친 버그

`compare`·`benchmark`는 조회가 `useEffect(…, [])`로 **마운트 1회**뿐이었습니다.
품목을 자동 선택해도 데이터가 갱신되지 않아 **select 표시와 표 내용이 어긋났습니다.**
의존성을 `[hs]`·`[hs, country]`로 바꾸고, `compare`의 중복 `load()` 호출을 제거했습니다.

### 빈 상태 안내 — `components/empty-items.tsx` (신규)

## 7. 공용 컴포넌트화 — 복사·붙여넣기 정리

같은 UI가 페이지마다 복사되어 조금씩 어긋나 있었습니다. 정의를 한 곳으로 모았습니다.

### 7-1. 알림 벨 — `components/alert-bell.tsx` (신규)

13곳에 **7가지 변종**으로 흩어져 있었습니다.

| 문제 | 범위 |
|---|---|
| `asChild`+`<Link>` 누락 → **눌러도 알림센터로 안 감** | 8개 페이지 |
| 빨간 점에 조건이 없어 **모두 읽음 처리해도 안 사라짐** | 10개 페이지 |

→ `GET /alerts?unread_only=true` 로 미읽음 수를 조회해, **0건이면 점을 숨기고 1건 이상이면 개수 표시**(`9+` 상한).
`/dashboard`는 이미 `alertCount` 를 계산해두고도 점에 연결하지 않은 상태였습니다.

같은 화면에서 읽음 처리했을 때도 즉시 반영되도록 이벤트를 뒀습니다.

```
알림 읽음 → notifyAlertsUpdated() → window 이벤트 → 벨이 재조회
페이지 이동 → 서버에 저장된 읽음 상태를 새 벨이 조회
```

검증: 미읽음 3건 → `모두 읽음 처리` → 같은 화면 배지 사라짐 → `/dashboard`·`/benchmark` 새로 열어도 배지 없음.

### 7-2. 사용자 아바타 — `components/user-avatar.tsx` (신규)

14곳에 이니셜이 직접 써넣어져 있었습니다 — 대부분 `SW`, `/items`만 `SG`.
로그인한 사람이 누구든 같은 글자가 보이고, 프로필 사진도 반영되지 않았습니다.

표시 규칙(`initialsOf()`):

| 조건 | 표시 |
|---|---|
| `picture_url` 있음 | 업로드한 이미지 |
| 한글 이름 | 앞 두 글자 (`전상욱` → `전상`) |
| 영문 이름 | 성·이름 첫 글자 (`Jane Doe` → `JD`) |
| 이름 없음 | 이메일 앞 두 글자 |
| 미로그인·조회 실패 | 사람 아이콘 |

프로필 저장 시 `notifyProfileUpdated()` 로 모든 화면 아바타를 갱신합니다.

`/settings`의 큰 프로필 편집기(h-20)와 팀원 목록 아바타는 성격이 달라(편집 중 미리보기 / 타인)
공용 컴포넌트로 바꾸지 않고 유지했습니다. 단, `initials` 계산은 같은 함수를 쓰도록 통일했습니다.

검증: 목 API의 사용자를 `전상욱` → `김민지` 로 바꾸자 5개 페이지가 모두 `전상` → `김민` 으로 따라왔습니다.

### 7-3. 로고 중복

데스크탑에서 사이드바 로고와 페이지 헤더 로고가 **동시에 보였습니다.**

페이지 헤더 로고 15곳에 `lg:hidden` 을 붙여 데스크탑에서만 숨겼습니다.
모바일은 사이드바가 없으므로 헤더 로고가 유일한 브랜딩으로 남습니다.

| 화면 | 사이드바 | 페이지 헤더 | 보이는 로고 |
|---|---|---|---|
| 데스크탑 | 보임 | 숨김 | **1개** |
| 모바일 | 없음 | 보임 | **1개** |

`/dashboard`는 로고가 `<Link>`가 아닌 `<div>`라 별도 처리했습니다.

**부수 회귀와 수정:** 로고를 숨기자 `justify-between`의 보이는 자식이 하나만 남아
종·아바타가 왼쪽으로 밀렸습니다. 우측 그룹에 `ml-auto` 를 넣어 14곳을 고쳤습니다.

**접힌 사이드바:** 접으면 로고가 완전히 사라졌습니다. 폭이 64px라 로고와 버튼을 나란히 둘 수 없어
**로고 아이콘 위 / 펼치기 버튼 아래**로 세로 배치했습니다. 15개 페이지에서 아이콘 클릭 시
`/dashboard`로 이동하는 것을 확인했습니다.

## 8. 데이터 정확성 — `/risks/[hsCode]`

`GET /risks?hs_code=` 는 `as_of_date` 별 **이력 전체**를 반환합니다([risks.py](../backend/app/api/v1/risks.py) 에 최신값 필터 없음).
`/compare` 는 국가별 최신값으로 dedupe 하는데 이 페이지는 하지 않아 세 가지가 함께 깨졌습니다.

| 증상 | 전 | 후 |
|---|---|---|
| 목록 행 수 | 120 (같은 국가 반복) | **20** |
| 중복 국가 | 독일 44점/41점, 아르헨티나 43점/40점 등 | **없음** |
| `분석 공급국` 집계 | `120개국` (행 수를 셈) | **`20개국`** |
| 콘솔 `duplicate key` 경고 | 발생 | 없음 |
| 대표 국가의 6지표 | 정렬 안 된 원본 첫 행 → **옛 스냅샷 가능** | 최신 스냅샷 |

`/compare` 와 같은 패턴(`Map` + `as_of_date` 비교)을 적용했습니다.

> 참고: 대시보드(`latestRiskRows()`), `/compare`, `/risks` **세 곳이 같은 dedupe 로직을 각각 구현**하고 있습니다.

## 9. 접근성 — `/recommendations` 중첩 버튼

국가 카드 전체가 `<button>` 인데 그 안에 `거래중`/`관심`/`해제` 토글 `<button>` 3개가 들어 있었습니다.
HTML에서 버튼 중첩은 금지이며 React가 hydration 에러를 냅니다(DOM에 12개 존재).

바깥을 `<div role="button" tabIndex={0}>` 으로 바꾸고 안쪽 토글은 네이티브 `<button>` 으로 유지했습니다.

| 항목 | 처리 |
|---|---|
| 키보드 조작 | `Enter`·`Space` 로 활성화(`preventDefault` 로 스페이스 스크롤 방지) |
| 포커스 표시 | `focus-visible:ring-2 focus-visible:ring-blue-500` |
| 커서 | `cursor-pointer` (div 기본값 없음) |

결과: `button button` 12개 → **0개**.

## 개발 환경 주의사항

프로젝트가 iCloud 동기화되는 `Documents/` 안에 있어, `.next/types/` 에 ` 2` 가 붙은
**중복 사본이 반복 생성**됩니다. 이 사본들이 `(app)/` 이전의 옛 경로를 참조해
`tsc` 가 가짜 에러를 뱉습니다. `tsc` 결과가 이상하면 이걸 먼저 의심하세요.

```bash
find Frontend/.next -name "* 2.*" -delete
```

근본 해결은 프로젝트를 iCloud 동기화 밖으로 옮기거나 `Frontend/.next` 를 동기화 제외로 두는 것입니다.
